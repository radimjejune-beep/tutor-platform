# Lessonfold: сайт, админка и бот

Один сервис на Node.js и PostgreSQL:

- **Публичный сайт** на вашем домене: витрина уроков по учебникам, бесплатный урок целиком, оферта, политика обработки данных и сведения о продавце.
- **Админка** `/admin` для вас и коллег: загрузка HTML, PDF и скриншотов уроков, цены, статусы, учебники, реквизиты, администраторы, статистика и журнал действий.
- **Оплата на сайте** через ЮKassa: покупатель указывает почту, принимает оферту, платит картой или СБП и сразу попадает на страницу скачивания. Ссылка приходит письмом, потерянные ссылки можно запросить на странице «Мои уроки».
- **Telegram-бот** (необязательно): бесплатный урок, каталог и покупка через страницу оплаты ЮKassa, файлы приходят в бот. Без `BOT_TOKEN` сервис работает как сайт без бота. Каталог у сайта и бота общий.

Файлы уроков хранятся в базе, а не на диске, поэтому деплой их не стирает.

## Бот

Telegram-бот, который выдаёт интерактивные уроки: бесплатный урок, каталог по учебникам, покупка, предзаказ модуля, личные ссылки для телефона, раздел «Мои уроки», напоминание после бесплатного урока и команды для админа.

Стек: Node.js 20+, PostgreSQL. Зависимости: `pg`, `pdf-lib`. Бот работает через long polling, вебхук не нужен. В том же процессе работает веб-сервер для личных ссылок на уроки и страниц оферты и политики.

## Что умеет

- **Бесплатный урок.** Кнопка в меню или ссылка `t.me/<бот>?start=free_sp6-3a`. Бот присылает HTML-урок с ником покупателя, PDF со штампом и личную ссылку для телефона.
- **Каталог.** Путь учебник → класс → модуль → урок или пакет. Уроки, которые уже есть у пользователя, отмечены галочкой.
- **Покупка.** Бот показывает оферту и присылает кнопку «Оплатить» на страницу ЮKassa. После оплаты файлы приходят в бот сами. Повторное уведомление о том же платеже не создаёт вторую покупку.
- **Предзаказ пакета.** Готовые уроки приходят сразу. Остальные бот присылает сам, когда урок выходит: после деплоя или по команде `/release`.
- **«Сообщить о выходе»** для уроков со статусом «скоро».
- **«Мои уроки»:** повторная отправка файлов и ссылки.
- **Напоминание.** Через `FOLLOWUP_HOURS` после бесплатного урока бот один раз пишет тем, кто ещё ничего не купил.
- **Админ** (ID из `ADMIN_IDS`):
  - `/stats`: пользователи, конверсия, выручка, источники `/start`;
  - `/grant @ник код`: выдать урок вручную;
  - `/release`: разослать вышедшие уроки;
  - `/followups`: отправить напоминания сейчас;
  - `/reload`: перечитать каталог.
- **Ссылки с меткой источника:** `t.me/<бот>?start=src_vk` попадает в `/stats`. Ссылка `?start=p_sp6-m3` сразу открывает товар.

## Установка на свой сервер (VPS)

Подойдёт любой VPS в России с Ubuntu 22.04 или 24.04 (Timeweb Cloud, Selectel, Beget и т. п.): 1 ядро, 1-2 ГБ памяти, 10-15 ГБ диска. Сервер должен быть в России: по ч. 5 ст. 18 152-ФЗ данные покупателей из России записываются и хранятся в базах на территории России.

1. **Сервер.** Закажите VPS с Ubuntu 24.04. Хостинг пришлёт IP-адрес и пароль root.
2. **Домен.** У регистратора домена создайте A-запись: домен → IP сервера. Для `www` тоже A-запись на тот же IP.
3. **Архив на сервер.** На своём компьютере: `scp lessonfold.zip root@IP:/root/`
4. **Установка.** Подключитесь `ssh root@IP` и выполните:
   ```
   apt-get update && apt-get install -y unzip
   unzip -o lessonfold.zip && cd lessonfold-bot
   bash deploy/install.sh
   ```
   Скрипт спросит домен, токен бота, логин и пароль админки, ключи ЮKassa (их можно добавить позже) и сам поставит Node.js, PostgreSQL, HTTPS, автозапуск и ежедневную копию базы.
5. **ЮKassa.** В кабинете ЮKassa укажите адрес уведомлений `https://ваш-домен/api/yookassa`.
6. **Telegram ID.** Напишите боту `/id`, впишите число в `ADMIN_IDS` в `/etc/lessonfold.env` и выполните `systemctl restart lessonfold`.

Обновление: загрузите новый архив, распакуйте и снова запустите `bash deploy/install.sh`. Настройки и база сохранятся.

Полезные команды:
- журнал: `journalctl -u lessonfold -f`
- перезапуск после правки настроек: `systemctl restart lessonfold`
- резервные копии базы: `/var/backups/lessonfold` (14 дней). Раз в месяц скачивайте свежую копию к себе: `scp root@IP:/var/backups/lessonfold/*.dump .`
- восстановление из копии: `systemctl stop lessonfold && runuser -u postgres -- pg_restore --clean --if-exists -d lessonfold файл.dump && systemctl start lessonfold`

## Рядом с платформой репетитора на RelaxDev (без новой базы)

Бот можно запустить отдельным проектом в том же аккаунте RelaxDev и хранить его данные в базе платформы (`db_tutor_platform`). Таблицы бота лежат в отдельной схеме `lessonfold`, поэтому с таблицами платформы (`users`, `files`, `settings` и другими) они не пересекаются.

1. В RelaxDev создайте новый Node-проект из этого архива: корень проекта, команда запуска `npm start`.
2. В переменных окружения укажите:
   - `DATABASE_URL`: та же строка подключения, что у проекта платформы (скопируйте из его настроек);
   - `DB_SCHEMA=lessonfold`;
   - `BOT_TOKEN`, `PUBLIC_URL` (адрес, который RelaxDev выдал этому проекту, или ваш домен), `ADMIN_LOGIN`, `ADMIN_PASSWORD`, `YOOKASSA_SHOP_ID`, `YOOKASSA_SECRET_KEY`.
3. Запустите проект и проверьте `PUBLIC_URL/health`. Схема и таблицы создадутся сами.
4. Резервная копия базы платформы теперь включает и данные бота.

Проверьте в RelaxDev лимит размера базы: файлы уроков хранятся в базе, один урок с озвучкой весит около 3 МБ.

## Запуск на RelaxDev (вместо своего сервера)

1. **Бот.** В @BotFather: `/newbot`, задайте имя и адрес, получите токен.
2. **База.** Создайте базу PostgreSQL на RelaxDev. Таблицы сервис создаст сам при первом запуске.
3. **Проект.** Новый Node-проект из архива или репозитория, корень проекта, команда запуска `npm start`.
4. **Переменные окружения** по `.env.example`. Обязательно: `DATABASE_URL`, `PUBLIC_URL`, `ADMIN_LOGIN`, `ADMIN_PASSWORD`. Для оплаты: `YOOKASSA_SHOP_ID`, `YOOKASSA_SECRET_KEY`. Для писем: `SMTP_*`, `MAIL_FROM`. Бот: `BOT_TOKEN` (можно не задавать). Переменную `CATALOG_FILE` не задавайте: тогда каталог хранится в базе и правится в админке.
5. **Первый запуск.** Сервис перенесёт `catalog.json` и файлы из `content/` в базу и создаст первого админа. Проверьте `PUBLIC_URL/health`: должно быть `ok`.
6. **Админка.** Откройте `PUBLIC_URL/admin`, войдите, на вкладке «Реквизиты и ссылки» впишите ФИО, ИНН, контакт, канал и дату оферты. Они сразу подставятся в оферту, политику и подвал сайта. После входа уберите `ADMIN_PASSWORD` из переменных окружения: он нужен только для первого запуска.
7. **Коллеги.** Вкладка «Администраторы» → добавить логин и пароль. Каждый админ видит всё; все действия пишутся в журнал на вкладке «Статистика».
8. **Бот** (если включён). Напишите боту `/id`, впишите свой ID в `ADMIN_IDS`, перезапустите сервис.

Важно: сервис должен работать в одном экземпляре. Два процесса с одним токеном мешают друг другу, бот тогда пишет в лог ошибку 409.

## Домен: как сделать сайт публичным

1. Купите домен у российского регистратора (REG.RU, RU-CENTER, Timeweb). Не используйте в домене названия учебников и издательств: это чужие товарные знаки. Подойдёт `lessonfold.ru` или похожий, если свободен.
2. В настройках проекта на RelaxDev добавьте свой домен. RelaxDev покажет, какую DNS-запись создать (обычно CNAME или A-запись).
3. Создайте эту запись в панели регистратора и подождите от 15 минут до суток.
4. Включите HTTPS (сертификат Let's Encrypt) в настройках проекта, если он не включился сам.
5. Поменяйте `PUBLIC_URL` на `https://ваш-домен` и перезапустите сервис. Ссылки на оферту в боте и личные ссылки на уроки начнут вести на домен.
6. Добавьте сайт в Яндекс Вебмастер и укажите `https://ваш-домен/sitemap.xml`.

## Как добавить урок через админку

1. Соберите урок с меткой `{{BUYER}}` вместо имени покупателя: `python3 build.py '{{BUYER}}' lesson.html`. Админка предупредит, если метки нет.
2. Админка → «Уроки» → «+ Урок». Заполните код (латиница, например `sp5-2b`), названия, описание, учебник, класс или уровень, раздел и модуль.
3. Загрузите HTML и PDF, добавьте 3-6 скриншотов экранов с подписями. Скриншоты уменьшаются и переводятся в WebP прямо в браузере.
4. Поставьте цену и статус «В продаже» и нажмите «Опубликовать». Если чего-то не хватает (нет файла, цены, модуля), админка покажет список.
5. После публикации бот сам разошлёт урок тем, кто купил предзаказ пакета, и тем, кто нажал «Сообщить о выходе».

Статусы: «В продаже», «Предзаказ» (только для пакетов), «Готовится», «Скрыт» (не виден на сайте и в каталоге бота, но остаётся у купивших). Удалить можно только скрытый товар.

Без админки, из файла: задайте `CATALOG_FILE=catalog.json`, положите файлы в `content/<код>/` и пропишите пути в каталоге. Этот режим нужен для тестов.

## Безопасность

- Пароли админов хранятся в виде хеша scrypt, сессия живёт 14 дней в cookie `HttpOnly`, `SameSite=Strict`, только для `/admin`.
- 10 неудачных входов с одного адреса блокируют вход на 15 минут.
- Изменения в админке принимаются только со своей страницы (заголовок и проверка Origin).
- Платные уроки и PDF наружу не отдаются: публичны только скриншоты и бесплатный урок. Каждая выдача покупателю вшивает в файл его ник и ID.
- Сайт не ставит cookie посетителям, не использует сторонние шрифты и счётчики, поэтому для посетителей не нужен баннер cookie.

## Оплата на сайте через ЮKassa

1. **Магазин.** Зарегистрируйтесь в ЮKassa как самозанятый (yookassa.ru), подключите магазин. При подключении проверьте в личном кабинете, что включена передача чеков в «Мой налог». Если её нет, чек после каждой оплаты выбивается вручную: список оплат в админке, вкладка «Заказы».
2. **Ключи.** В кабинете ЮKassa: Интеграция → Ключи API. `shopId` запишите в `YOOKASSA_SHOP_ID`, секретный ключ в `YOOKASSA_SECRET_KEY`. Для проверки используйте тестовый магазин и тестовые карты ЮKassa.
3. **Уведомления.** Интеграция → HTTP-уведомления: адрес `https://ваш-домен/api/yookassa`, события `payment.succeeded`, `payment.canceled`, `refund.succeeded`. Сервер не доверяет содержимому уведомления и каждый раз сам запрашивает статус платежа. Если уведомление не дошло, статус проверяется при открытии страницы заказа и раз в 15 минут.
4. **Чек по 54-ФЗ.** `YOOKASSA_RECEIPT=1` включайте, только если ЮKassa требует передавать данные чека. Самозанятому обычно не нужно.
5. **Возврат.** Админка → «Заказы» → «Возврат». Деньги вернутся через ЮKassa, доступ к файлам по заказу закроется. Чек аннулируйте в «Мой налог».

## Письма покупателям

Письмо со ссылкой на заказ, письма о выходе уроков из предзаказа и письмо «Мои уроки» уходят через SMTP. Подойдёт почта на своём домене в Яндекс 360 или Mail.ru для бизнеса (серверы в России, это важно для закона о персональных данных):

```
SMTP_HOST=smtp.yandex.ru
SMTP_PORT=465
SMTP_SECURE=1
SMTP_USER=lessons@ваш-домен
SMTP_PASS=пароль приложения
MAIL_FROM=lessons@ваш-домен
```

Без почты всё работает, но письма не уходят: в админке у такого заказа написано «не ушло», ссылку можно скопировать кнопкой «Ссылка» и отправить покупателю вручную.

## Оплата в боте через ЮKassa

Бот не выставляет счёт внутри Telegram. По п. 6.2 правил Telegram для разработчиков ботов цифровые товары внутри бота продаются только за Telegram Stars, а за оплату через сторонних провайдеров бот могут скрыть или удалить. Поэтому кнопка «Купить» создаёт заказ в ЮKassa и присылает кнопку «Оплатить» со ссылкой на страницу оплаты ЮKassa (карта, СБП).

Как проходит покупка:

1. Покупатель нажимает «Купить». Бот присылает ссылки на оферту и политику и кнопку «Оплатить 490 ₽».
2. Покупатель платит на странице ЮKassa. ЮKassa возвращает его обратно в бот по ссылке `t.me/<бот>?start=paid_…`.
3. ЮKassa присылает уведомление на `PUBLIC_URL/api/yookassa`. Сервис сам перепроверяет статус платежа и сумму запросом к ЮKassa, после этого бот присылает файлы, а вам приходит уведомление. Если уведомление не дошло, оплату подтвердит возврат покупателя в бот или проверка раз в 15 минут.
4. Заказ виден в админке на вкладке «Заказы» (вместо почты там ник в Telegram). Возврат из админки закрывает доступ к уроку в боте.

Настройка:

1. **Магазин ЮKassa** для самозанятого. Включите в кабинете передачу чеков в «Мой налог». Если её нет, бот в каждом уведомлении об оплате напомнит выбить чек вручную.
2. **Ключи API** (Интеграция → Ключи API) запишите в `YOOKASSA_SHOP_ID` и `YOOKASSA_SECRET_KEY`. Эти же ключи работают и для сайта.
3. **HTTP-уведомления.** В кабинете ЮKassa: Интеграция → HTTP-уведомления, адрес `https://ваш-домен/api/yookassa`, события `payment.succeeded`, `payment.canceled`, `refund.succeeded`.
4. **Проверка.** Сначала используйте тестовый магазин ЮKassa и тестовую карту: купите урок в боте и убедитесь, что файлы и уведомление пришли. Потом замените ключи на боевые.

Токен из @BotFather → Payments больше не нужен.

## Тест

```
TEST_DATABASE_URL=postgres://... npm test
TEST_DATABASE_URL=postgres://... node test/web.js   # сайт и админка, база очищается
TEST_DATABASE_URL=postgres://... node test/pay.js   # оплата на сайте, письма, возвраты, база очищается
```

Сквозной тест поднимает поддельный Telegram API и проходит весь путь: `/start`, бесплатный урок, личная ссылка, каталог, кнопку оплаты ЮKassa, возврат в бот до и после оплаты, уведомление ЮKassa, отмену оплаты, повтор платежа, предзаказ, выход урока, «Мои уроки», напоминание и админ-команды.

## Курсы на учебный год (версия 2.3.0)

Курс: все уроки к учебнику для одного класса одной покупкой, например «Spotlight 6, весь курс».
- В админке: «Уроки» → «+ Курс на год». Укажите учебник, класс, цену и статус («Предзаказ», пока уроков мало, или «В продаже»). Модуль указывать не нужно.
- Состав курса считается сам: в него входят все уроки этого учебника и класса, включая те, что выйдут позже. Покупатель курса получает готовые уроки сразу, а новые бот присылает сам при публикации.
- В боте появилась кнопка «Курсы на год» и команда /courses, а в каждом классе курс стоит первой кнопкой над модулями. На сайте курс показан первым в списке учебника.
- Пустой курс (без готовых уроков) нельзя поставить в продажу: только «Предзаказ» или «Скоро».
- Тест: `node test/course.js`, сценарий в боте проверяется в `test/e2e.js`.
